# muto-wiki

내 업무와 학습에서 쌓이는 지식을 축적하는 개인 위키.
[Andrej Karpathy의 LLM Wiki 패턴](https://gist.github.com/karpathy/442a6bf555914893e9891c11519de94f)을 따른다.

**핵심 아이디어** — 자료를 검색할 때마다 다시 읽는 대신, **한 번 정리해서 계속 최신으로 유지한다.**
내가 자료를 넣고 질문을 던지면, 에이전트가 읽고 정리하고 교차참조를 이어붙인다.
질문할수록 위키가 커지고, 시간이 갈수록 답이 빨라진다.

| 파일 | 역할 |
|---|---|
| **README.md** (이 파일) | 사람이 읽는 사용설명서 |
| **CLAUDE.md** / AGENTS.md | 에이전트가 따르는 규칙 (스키마). 규칙을 바꾸려면 여기를 고친다 |

---

## 시작하기

### 지식을 넣고 꺼낼 때 — 에이전트

이 폴더에서 Claude Code 또는 Codex를 연다.

```bash
cd /Users/muto/branch/muto-wiki
claude          # 또는 codex
```

Claude Code는 **열 때 자동으로 최신을 내려받고, 작업을 마치면 올린다.**
Codex는 훅이 없으므로 `CLAUDE.md` 규칙에 따라 직접 실행한다 (아래 [git 동기화](#git-동기화) 참조).

### 읽고 탐색할 때 — Obsidian

저장소 루트가 그대로 Obsidian 볼트다. Obsidian에서 **"보관함으로 열기"** 로 `/Users/muto/branch/muto-wiki` 를 선택한다.

- `wiki/index.md` 부터 본다 — 전체 목차
- 그래프 뷰로 페이지 간 연결을 본다
- 모바일에서도 같은 볼트를 열 수 있다 (git 동기화 필요)

## 네 가지 사용법

### 1. 자료 넣기

**방법 A — 파일로 넣기.** `raw/` 폴더에 파일을 떨어뜨리고 한마디 한다.

```
자료 넣었어
```

**방법 B — 그냥 붙여넣기.** 대화창에 내용·링크를 붙여넣는다.

```
이거 정리해줘
<슬랙에서 복사한 장애 대응 내용>
```

```
https://bugs.mysql.com/bug.php?id=119309 이거 위키에 넣어줘
```

그러면 에이전트가:

1. **기존 페이지를 먼저 찾는다** — 새 페이지를 만드는 건 마지막 수단이고, 기본은 기존 페이지에 흡수시키는 것
2. 기술 지식과 업무 기록이 섞여 있으면 **나눠서** 각각 넣고 서로 링크한다
3. 각 페이지의 **핵심 Takeaway를 다시 쓴다**
4. 관련 페이지들에 교차참조를 연결한다
5. `wiki/index.md`와 `wiki/log.md`를 갱신한다
6. `raw/`의 원본을 `raw/archive/`로 **옮긴다** (삭제하지 않는다)

> `raw/`는 내가 넣는 곳이다. 에이전트는 읽기만 하고 고치거나 지우지 않는다.

**넣을 만한 것**
- DB 운영 설정값, 쿼리, 신규 제품 정리, 버전·버그 리포트
- 트러블슈팅, 성능개선, 사내 강의 자료, 일/주/월 업무 정리
- 개인 일정, 관심 주식·부동산

**넣지 말 것** — 계정, 비밀번호, 토큰, 접속 문자열, 내부 IP, 고객 데이터.
섞여 있으면 그 부분을 빼고 넣는다. 위키에는 위치만 남긴다 (`"자격증명은 사내 vault 참조"`).

---

### 2. 질문하기

그냥 물어보면 된다.

```
Aurora 업그레이드 전에 확인할 항목 알려줘
```
```
MySQL 8.0.42 써도 되나?
```
```
PG bloat 장애 났을 때 뭐부터 봐?
```
```
지난달에 내가 한 일 정리해줘
```

답변은 **근거 페이지를 `[[페이지명]]`으로 인용**한다.

- 위키에 없으면 **없다고 먼저 말한다.** 일반 지식으로 답할 때는 그렇다고 밝힌다
- `status: draft` 페이지를 근거로 쓰면 미검증임을 알려준다
- 답변 과정에서 나온 결론이 재사용할 만하면 **페이지로 환원한다** — 질문이 위키를 키운다

---

### 3. 건강검진

```
건강검진해줘
```

전수 점검 후 **리포트를 먼저 내고, 승인받고 고친다.** 임의로 손대지 않는다.

| 점검 항목 | 무엇을 보나 |
|---|---|
| 깨진 wikilink | 없는 페이지를 가리키는 링크 |
| 고아 페이지 | 들어오는 링크가 하나도 없는 페이지 |
| 단방향 링크 | A→B는 있는데 B→A가 없는 쌍 |
| Takeaway 누락·노후 | 첫 블록이 callout이 아니거나 본문 대비 낡음 |
| frontmatter 누락 | 필수 필드 결손 |
| stale | 90일 넘게 손대지 않은 페이지 |
| **모순** | 페이지 간 수치·버전·한도가 어긋남 — **가장 중요** |
| index 불일치 | 파일 목록과 목차가 다름 |
| 미처리 원본 | `raw/`에 남았는데 위키에 반영 안 된 파일 |
| Notion 지연 | 동기화 후 수정된 페이지 |
| 승격 후보 | `draft`인데 공식 출처 대조가 끝난 페이지 |
| 민감정보 | 계정·토큰·내부 IP 흔적 (발견 즉시 보고) |

한 달에 한 번, 또는 자료를 여러 건 몰아 넣은 뒤에 돌리면 좋다.

---

### 4. Notion 동기화

```
노션 동기화해줘
```

**단방향(`wiki/` → Notion)이고, 요청할 때만 실행한다.** wiki가 항상 진실이다.

- 첫 실행 때 **대상 부모 페이지를 확인받는다.** 임의로 만들지 않는다
- 마지막 동기화 이후 수정된 페이지만 올린다 (전체 재업로드 안 함)
- Takeaway callout은 Notion callout 블록으로 옮긴다

> **Notion MCP가 연결된 Claude 세션에서만 가능하다.** Codex 등에서는 안 된다.
> Notion에서 직접 고친 내용은 회수하지 않는다 — 편집은 항상 `wiki/`에서 한다.

## 구조

```
muto-wiki/
├── README.md          이 파일 — 사용설명서
├── CLAUDE.md          에이전트 규칙 (스키마)
├── AGENTS.md          → CLAUDE.md 심볼릭 링크 (Codex·기타 에이전트용)
├── scripts/sync.sh    git 동기화
├── raw/               원본 자료 — 내가 넣고, 에이전트는 읽기만
│   └── archive/       위키 반영이 끝난 원본
└── wiki/              정리된 지식 — 에이전트가 작성·관리
    ├── index.md       전체 목차 (여기서만 분류한다)
    ├── log.md         작업 이력
    └── *.md           위키 페이지
```

**`wiki/`에는 하위 폴더를 만들지 않는다.** 분류는 오직 `index.md`의 카테고리 절로 한다.
폴더가 없으니 링크는 항상 `[[페이지명]]` — 경로 접두어가 붙지 않고, 분류를 바꿔도 링크가 깨지지 않는다.

카테고리는 5개: `db운영` · `업무기록` · `개인` · `참고자료` · `종합원칙`

## 페이지 생김새

모든 페이지는 **핵심 Takeaway callout으로 시작한다.** 제목보다도 먼저.

```markdown
---
title: MySQL/Aurora MySQL 운영 지식
category: db운영
tags: [mysql, aurora, backup]
summary: 200자 이내 한 줄 요약
sources: [사내 강의 2026-07, MySQL 8.0 릴리스 노트]
status: draft          # draft | reviewed | verified | disputed | archived
created: 2026-08-04
updated: 2026-08-15
notion_page_id: null
notion_synced: null
---

> [!tip] 핵심 Takeaway
> - 회수 릴리스(8.0.29, 8.0.38/8.4.1)는 업그레이드 후보에서 즉시 제외 — 버전 선정 자동화의 하드 필터
> - 복구 테스트 없는 백업은 백업이 아니다. 주간 점검 1순위 항목

# MySQL/Aurora MySQL 운영 지식

본문... [[operational-queries]] 처럼 교차참조한다.
```

Takeaway는 **내용 요약이 아니라 행동 지침**이다. "그래서 내가 뭘 해야/하지 말아야 하는가"에 답한다.

| ❌ 요약 | ✅ 행동 지침 |
|---|---|
| MySQL 8.0.42에 파티션 pruning 버그가 있다 | 8.0.42는 증상이 없어도 안전한 게 아니다 — INSERT 이력이 없어 미노출일 뿐. 업그레이드 게이트에서 차단 |

본문 표기 규칙:

- 표기 없음 = 자료가 실제로 말한 것
- `^[inferred]` = 자료가 직접 말하지 않은 추론
- `^[ambiguous]` = 자료끼리 어긋나거나 원문이 모호함

**구술·사내 자료는 공식 문서와 대조하기 전까지 `verified`로 올리지 않는다.**
실제로 이 규칙이 없어서 오류 5건이 나왔다 — [verbal-source-verification-policy](wiki/verbal-source-verification-policy.md)

## git 동기화

**열 때 최신을 내려받고, 마칠 때 올린다. 충돌하면 원격이 항상 이긴다.**
여러 장비에서 쓰는 개인 위키라, 다른 기기가 올린 내용이 로컬의 작업 중 상태보다 신뢰도가 높다.

| 환경 | 동작 |
|---|---|
| **Claude Code** | `.claude/settings.json` 훅이 자동 실행. 손댈 것 없음 |
| **Codex 등** | 직접 실행 — 시작 전 `pull`, 위키를 고친 뒤 `push` |

```bash
bash scripts/sync.sh pull    # 세션 시작 시
bash scripts/sync.sh push    # 작업 종료 시
```

**브랜치를 만들지 않는다.** 모든 커밋은 `main`에 직접 한다. 자동 동기화가 `main`에 커밋하므로 브랜치를 만들면 바로 갈라진다.

---

## 문제 해결

### push가 안 될 때

`sync.sh`는 실패해도 작업을 막지 않도록 조용히 넘어간다. 안 올라간 것 같으면 직접 확인한다.

```bash
git status
git log --oneline -3
git rev-list --left-right --count origin/main...main   # 오른쪽 숫자가 안 올라간 커밋 수
git push                                                # 실제 오류 메시지 확인
```

**`could not read Username for 'https://github.com'`** — 자격증명이 없다.
세션에서 `! git push` 로 한 번 직접 실행해 인증하면 osxkeychain에 저장되어 이후 자동 push가 동작한다.
SSH를 쓰려면 공개키를 GitHub에 등록하고 remote를 바꾼다:

```bash
git remote set-url origin git@github.com:mutocho/muto-wiki.git
```

### 동기화가 아무 일도 안 할 때

`sync.sh`는 **`main` 브랜치가 아니면 조용히 종료한다.** `git branch --show-current`로 확인한다.

### 다른 기기의 변경과 충돌했을 때

`-X theirs`로 자동 해소된다 — **원격이 이긴다.**
로컬에서 작업 중이던 내용이 밀릴 수 있으므로, 중요한 편집은 마치고 나서 다른 기기를 연다.

### Obsidian에서 링크가 깨져 보일 때

`wiki/`에 하위 폴더가 생겼을 가능성이 높다. 플랫 구조를 지키면 생기지 않는다.
`건강검진해줘`로 깨진 링크를 찾는다.

## 규칙을 바꾸고 싶을 때

`CLAUDE.md` **하나만** 고친다. `AGENTS.md`는 심볼릭 링크라 자동으로 따라간다.

바꿀 만한 것 — 카테고리 추가, Takeaway 작성 기준, 건강검진 점검 항목, 적재 라우팅 규칙.
`CLAUDE.md` §0(사용자 컨텍스트)은 **모든 Takeaway의 판단 기준**이므로, 업무나 방향성이 바뀌면 여기부터 갱신한다.
